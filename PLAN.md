# План разработки SaaS-платформы

## Шаг 1: Инициализация проекта Next.js
- Выполнить команду `npx create-next-app@latest . --typescript --app --no-eslint --no-tailwind --import-alias "@/*"`
  (Или эквивалентную команду для инициализации в текущей директории с App Router, TypeScript, без ESLint и Tailwind, с алиасом @/*)
- Убедиться, что проект инициализирован корректно.

## Шаг 2: Установка и настройка Sass
- Установить sass: `npm install -D sass`
- Next.js имеет встроенную поддержку для Sass, поэтому дополнительной конфигурации не требуется.
- Проверить, что можно импортировать файлы с расширением .module.scss.

## Шаг 3: Создание базовой структуры папок
- Создать директорию `components` для общих компонентов.
- Внутри `components` создать директорию `ui` для базовых UI-компонентов (кнопка, ввод и т.д.).
- Создать директорию `styles` для глобальных стилей (если понадобится).
- Создать директорию `app` (уже есть от Next.js) для страниц и маршрутов.

## Шаг 4: Создание полиморфного компонента Button
- В `components/ui` создать файл `Button.tsx`.
- Реализовать компонент Button с пропсом `as: React.ElementType` (по умолчанию 'button').
- Поддерживать варианты: `variant` (primary, secondary), `size` (sm, md, lg), `disabled`.
- Использовать модульный Sass: создать `Button.module.scss` в той же директории.
- Определить стили для состояний, размеров и вариантов.
- Убедиться, что компонент работает как с `<button>`, так и с Next.js `Link`.

## Шаг 5: Запуск локальной сборки и линтера
- Запустить режим разработки: `npm run dev` (в терминале Fish).
- Убедиться, что нет ошибок компиляции и стилей.
- Запустить проверку типов: `npm run typecheck` (или `tsc --noEmit`).
- Если линтер не был установлен на шаге 1, можно запустить `npm run lint` (если ESLint был добавлен позже) или просто проверить типы.

## Примечания
- Все команды терминала должны быть написаны для Fish shell.
- Следовать правилам из CLAUDE.md: мобильный-first, без магических чисел, строго модульный Sass.
